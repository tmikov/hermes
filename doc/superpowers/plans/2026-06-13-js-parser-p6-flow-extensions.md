# JS Parser — Phase P6 (Flow ambiguous-expression grammar + Flow language extensions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) tracking. The C++ in `lib/Parser/JSParserImpl-flow.cpp` + the Flow call sites in `lib/Parser/JSParserImpl.cpp` IS the spec — port it faithfully from the cited line ranges; the byte-for-byte `parser_differential` vs `hermesc -dump-ast …` is the gate. **The header of record is `lib/Parser/JSParserImpl.h`** (in-tree, NOT `include/hermes/Parser/JSParserImpl.h`) — read its default args; default args are spec.

**Goal:** Port the rest of Flow: (1) the **ambiguous expression-level grammar** that needs `SavePoint` + message-suppression backtracking — typed arrows (sync + async), `as`/`as const`, parenthesized type-casts `(x: T)` + `CoverTypedIdentifier`, and type-arguments on call/`new`/optional-chain; and (2) the **Flow language extensions** — `enum`, `component`/`hook` syntax, `record`, `match`, and the `declare` statement family with `import type`/`export type` clauses. After P6 the Rust parser dumps byte-identically to `hermesc -dump-ast` (+ the matching hidden flag) over a plain + Flow-type + Flow-extensions corpus, leaving only TS (P7), JSX, and the Pre/Lazy passes.

**Architecture:** P5 left honest `// P6` markers at every site; this phase replaces them. The ambiguous expression grammar lands in `js/expressions.rs` (re-growing the dropped `AllowTypedArrowFunction`/`CoverTypedParameters`/`typeParams` signatures on `parse_assignment_expression`/`parse_conditional_expression`/`parse_arrow_function_expression`, plus the type-arg backtracking in the call/new/member sites). The extensions land in `js/flow/declarations.rs` (enum, component/hook, record, declare), a **new** `js/flow/match_.rs` (the match grammar), and `js/modules.rs` (`import type`/`export type`/Flow default exports). Reachability grows through four new `Context` flags that mirror C++ `Context` settings; the differential harness runs each gated corpus dir with the matching hidden hermesc flag on **both** binaries.

**Tech Stack:** the `ast` + `parser` + `support` crates; `cmake-build-asan/bin/hermesc` as the differential oracle.

**Spec:** `doc/superpowers/specs/2026-06-06-js-parser-design.md`. **Builds on P0–P5** (`plans/2026-06-06…p0/p1/p2`, `…p3`, `…p4`, `plans/2026-06-09-js-parser-p5-flow-types.md`).

### B. Message suppression — two distinct mechanisms (both already in `support`, unused until now)
Research located both in `rust/crates/support/src/manager.rs`; lexer lookahead already uses the suppress pattern (`lexer/lookahead.rs:84-126`). Confirm the exact API names in P6.0 and use consistently:
1. **Pure suppress** (drop messages produced during a speculative parse): C++ `SourceErrorManager::SaveAndSuppressMessages`. Rust: save/restore the suppressed-subsystem (`let saved = sm.suppressed_messages(); sm.set_suppressed_messages(Some(Subsystem::Parser)); … sm.set_suppressed_messages(saved);`). Used by: type-arg backtracking, typed-async-arrow, conditional-consequent backtrack.
2. **Defer-then-commit** (buffer messages; commit on success, discard on rollback): C++ `CollectMessagesRAII collect{&sm_, true}` + `collect.setDiscardMessages(false)`. Rust: `begin_collecting()` / `end_collecting(prev, discard)` (`manager.rs:927/941`; `discard=false`=commit, `true`=rollback). Used by: typed-arrow type-param head and return-type/predicate backtracking. **These collect/buffer APIs are implemented + tested but NOT yet used anywhere** — P6 is their first consumer; if an API gap surfaces, fix it in `support` with a golden test.
