**Goal:** Parse the full ECMAScript *module* grammar — `import` declarations (default / namespace / named specifiers, `from` clause, `with` import-attributes clause, bare module specifier), `export` declarations (`export {…}`, `export {…} from`, `export * from`, `export * as ns from`, `export default …`, `export var/let/const/function/class …`), and the `import(…)` / `import.meta` expression forms — so module programs dump byte-identically to `hermesc -dump-ast`. This closes the last P1/P2/P3 honest-error deferral set for standard JS (only Flow/TS remain, → P5–P7).

**Architecture:** Extend `impl<'gc,'ast,'ctx,'a> JSParserImpl<...>`. The declaration productions are statement-list-level — put them in a **new sibling `rust/crates/parser/src/js/modules.rs`** `impl` block (match the existing split-by-responsibility convention: `expressions.rs`/`statements.rs`/`functions.rs`/`classes.rs`). Declare `mod modules;` in `js/mod.rs`. The `import()`/`import.meta` *expression* forms go in `expressions.rs` (they live in `parse_optional_expression_except_new`). Each currently emits an honest `"… (parser phase P4)"` error — grep them: 2 in `statements.rs` (import-decl, export-decl, ~lines 134/142) + 1 in `expressions.rs` (`rw_import`, ~line 2115); P4 REPLACES each with the real parse. Nodes are built with the `ast` `new` constructors + `set_location`. Returns `Option<&'gc Node<'gc>>` / `bool`.

**Tech Stack:** the `ast` + `parser` crates; `hermesc` (`cmake-build-asan/bin/hermesc`) as the differential oracle.

**Spec:** `doc/superpowers/specs/2026-06-06-js-parser-design.md`. **Builds on P0+P1+P2+P3** (`plans/2026-06-06-js-parser-{p0-foundations,p1-expressions,p2-statements}.md`, `plans/2026-06-07-js-parser-p3-functions-classes.md`).
