# AST Phase 2 — Node-set codegen from `ESTree.def`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hand-written 4-kind node model with a committed generator (`gen_nodes.py`) that parses `include/hermes/AST/ESTree.def` (all FLOW/JSX/TS/Cover families ON) plus a hand-transcribed decoration table, emitting the full ~282-node `src/node.rs` (enum + per-kind structs + `NodeKind` with `_FIRST_`/`_LAST_` ranges + `is_*`/`as_*` accessors + the GC/read walks `visit_children` and `mark_lists`), wired into the existing GC arena.

**Architecture:** A Python generator following the project precedent (`gen_tables.py`, `gen_html_entities.py`): read a C++ `.def`, emit a committed, `// @generated`-marked Rust file, guard with anti-drift count asserts. `src/node.rs` becomes fully generated. The GC marker in `context.rs` already calls `node.visit_children(self)` and `node.mark_lists(&mut cb)` with signatures this plan preserves, so the storage layer is untouched. Builders (GC-allocating clone-with-change) and the JSON dumper are **later phases**; phase 2 emits only the data model + the read/GC walks.

**Tech Stack:** Python 3 (generator, committed, manually invoked), Rust 2021 / toolchain 1.96. Path deps unchanged: `support`, `atom_table`.

**Reference spec:** `doc/superpowers/specs/2026-06-03-ast-design.md` §2 (READ IT). **Source of truth:** `include/hermes/AST/ESTree.def` (node shapes — machine-parsed) and `include/hermes/AST/ESTree.h:264-501` (decoration classes — hand-transcribed into this plan's table; do **not** parse `ESTree.h`).

## Scope notes (read before starting — these are deliberate decisions, not gaps)

1. **`src/node.rs` becomes fully generated** (header `// @generated by gen_nodes.py from include/hermes/AST/ESTree.def — DO NOT EDIT`), exactly like `tables.rs`/`html_entities.rs`. The phase-1 hand-written model is deleted. `range()`, `metadata()`, `kind()`, `visit_children()`, `mark_lists()` are all generated (mechanical matches over every variant).
2. **Fields are idiomatic snake_case; the camelCase `.def` name is retained by the generator for the dumper.** `_typeParameters` → Rust field `type_parameters`, but the generator remembers the original `typeParameters` and bakes it as a literal JSON-key string when it emits the phase-4 dumper (`out.emit_key("typeParameters")`). This keeps `node.rs` idiomatic (no `#![allow(non_snake_case)]`) **and** yields byte-identical ESTree JSON — the camelCase name lives in the generator, not in the struct. (This is juno's model, minus its runtime snake→camel conversion: the literal is baked at generation time.) Decoration fields are likewise snake_cased (`sem_info`, `is_method_definition`, `dummy_param_list`, `label_index`, `buffer_id`, …; trailing `_` dropped); decorations aren't dumped, so their names are internal-only.
3. **Rust-keyword field names are raw-escaped.** `.def`/decoration fields whose snake_case form is a Rust reserved word — `await` (ForOfStatement), `async` (function-likes), `type` (TS), etc. — are emitted as `r#await` / `r#async` / `r#type`. The generator holds a Rust-keyword set (see Task 1 Step 2).
4. **`NodeKind` mirrors the C++ enum exactly** — `#[repr(u32)]`, in `.def` order, with interleaved `_NAME_First`/`_NAME_Last` sentinels — so `isa`/`dyn_cast` over a base range is the same `_First < kind < _Last` comparison the C++ uses (and the same ordering Sema/IRGen will reference later). File carries `#![allow(non_camel_case_types)]` for the sentinel names.
5. **Minimal `new` constructors are generated** (`XNode::new(metadata, <.def args>) -> Self`), defaulting all decoration fields. These are plain field-init constructors — **not** the phase-3 Builder (which adds GC allocation + clone-with-one-field-changed + visitor rebuild). Without them the 282-node model is effectively unconstructable in tests. (Flagged here so the reviewer sees this as an intentional, minimal inclusion.)
6. **`visit_children_mut` / functional-rebuild is deferred to phase 3** (it needs the Builder to allocate rebuilt nodes). Phase 2 emits `visit_children` (read) + `mark_lists` (GC) — the two walks the marker needs now. `tests/spine.rs` keeps its *hand-written* `double()` rebuild, which needs no generated mutate-walk.
7. **`ESTREE_IGNORE_IF_EMPTY` is parsed but not yet emitted** (it's a dumper concern). The generator records it for phase 4; phase 2 ignores those lines functionally.
8. **`NodeMetadata` is unchanged** (range + parens). `debugLoc` is not added (no consumer yet) — a documented minor gap, addable when the parser/dumper needs it.

### A. `.def` field-type → Rust mapping

| `.def` Type | optional flag | Rust field type | `new()` arg type | classification |
|---|---|---|---|---|
| `NodePtr` | `false` | `&'gc Node<'gc>` | `&'gc Node<'gc>` | immutable child |
| `NodePtr` | `true` | `Option<&'gc Node<'gc>>` | `Option<&'gc Node<'gc>>` | immutable child |
| `NodeList` | (any) | `NodeList<'gc>` | `NodeList<'gc>` | immutable child list |
| `NodeBoolean` | (any) | `Cell<bool>` | `bool` | value |
| `NodeNumber` | (any) | `Cell<f64>` | `f64` | value |
| `NodeLabel` | (any) | `Cell<NodeLabel>` | `NodeLabel` | value |
| `NodeString` | (any) | `Cell<NodeString>` | `NodeString` | value |

- `new()` wraps value args in `Cell::new(...)`; passes children/lists through directly.
- **Rust field name = `camel_to_snake(.def name)`, raw-escaped if a Rust keyword** (e.g. `typeAnnotation`→`type_annotation`, `await`→`r#await`). The generator also retains the original `.def` name (`json_name`) per field, for the phase-4 dumper's literal JSON keys. Dedup (algorithm E step 6) is by the **snake_case** field name.

### B. Decoration classes (hand-transcribed from `ESTree.h:264-501`)

Each entry: `name → (bases, own-fields)`. Own-field = `(field_name, rust_type, default_expr)` — the `field_name` shown is the **source** name; the emitted Rust field is `camel_to_snake(field_name)`, keyword-escaped (e.g. `semInfo`→`sem_info`, `dummyParamList`→`dummy_param_list`). The generator **flattens** a decoration by emitting its bases' fields first (recursively, base-first), then its own, **deduping by (snake_case) field name** (first occurrence wins).

### C. Base-range → decoration (automatic: every `ESTREE_FIRST(NAME, _)` range carries `<NAME>Decoration`)

```
FunctionLike→FunctionLikeDecoration   Statement→StatementDecoration   LoopStatement→LoopStatementDecoration
CallExpressionLike→CallExpressionLikeDecoration   MemberExpressionLike→MemberExpressionLikeDecoration
ClassLike→ClassLikeDecoration   Pattern→PatternDecoration   MatchPattern→MatchPatternDecoration
JSX→JSXDecoration   Flow→FlowDecoration   TS→TSDecoration   Cover→CoverDecoration
```

### D. Leaf `DecoratorTrait` map (hand-transcribed from `ESTree.h:530-581`)

```
BlockStatement→BlockStatementDecoration   StaticBlock→StaticBlockDecoration
BreakStatement→BreakStatementDecoration   ContinueStatement→ContinueStatementDecoration
ForStatement→ForStatementDecoration   ForInStatement→ForInStatementDecoration   ForOfStatement→ForOfStatementDecoration
CatchClause→CatchClauseDecoration   SwitchStatement→SwitchStatementDecoration   LabeledStatement→LabeledStatementDecoration
Identifier→IdentifierDecoration   Program→ProgramDecoration
```
(The C++ also specializes `DecoratorTrait<ClassLikeNode>`, but `ClassLike` is a base **range**, not a leaf node — its decoration already attaches via rule C. Ignore that one trait entry; leaf nodes `ClassDeclaration`/`ClassExpression` inherit `ClassLikeDecoration` through the range.)

### E. Per-leaf field composition (the generator's core algorithm)

For each leaf node `N` (an `ESTREE_NODE_*_ARGS`):
1. Start `fields = [metadata]`.
2. Append `.def` arg fields in order (mapping via table A).
3. Compute the **range chain**: `N`'s immediate base is the macro's `BASE` arg; follow `ESTREE_FIRST(range, parentBase)` links upward collecting every range until `Base`. Order them **outermost-first** (closest to `Base` first).
4. For each range in that order, append the flattened fields of `<range>Decoration` (rule C + flatten per B).
5. Append the flattened fields of `N`'s `DecoratorTrait` decoration (rule D; default `EmptyDecoration`).
6. **Dedup by field name**, first occurrence wins. (No real node hits a duplicate today, but dedup makes diamonds like `SwitchStatementDecoration`'s two bases safe.)

```rust
impl<'gc> Node<'gc> {
    pub fn kind(&self) -> NodeKind {
        match self {
            Node::Empty(_) => NodeKind::Empty,
            Node::Program(_) => NodeKind::Program,
            // ... one arm per leaf ...
        }
    }
    pub fn metadata(&self) -> &NodeMetadata<'gc> {
        match self {
            Node::Empty(n) => &n.metadata,
            Node::Program(n) => &n.metadata,
            // ... one arm per leaf ...
        }
    }
    pub fn range(&self) -> support::location::SMRange { self.metadata().range.get() }

    // Range predicates (one per ESTREE_FIRST range) — classof-style:
    pub fn is_function_like(&self) -> bool {
        let k = self.kind() as u32;
        (NodeKind::_FunctionLike_First as u32) < k && k < (NodeKind::_FunctionLike_Last as u32)
    }
    // ... is_statement, is_loop_statement, is_call_expression_like, is_member_expression_like,
    //     is_class_like, is_pattern, is_match_pattern, is_jsx, is_flow, is_ts, is_cover ...

    // Leaf accessors (one per leaf):
    pub fn as_identifier(&self) -> Option<&Identifier<'gc>> {
        if let Node::Identifier(n) = self { Some(n) } else { None }
    }
    // ... as_<leaf>() for every node ...

    pub fn visit_children<V: Visitor<'gc> + ?Sized>(&'gc self, v: &mut V) {
        match self {
            // leaves with no children:
            Node::NumericLiteral(_) => {}
            // single + optional + list + decoration-list children:
            Node::Program(n) => {
                for c in n.body.iter() { v.visit_node(c); }
                for c in n.decorations.get().iter() { v.visit_node(c); }
                for c in n.dummy_param_list.get().iter() { v.visit_node(c); }
            }
            Node::ForStatement(n) => {
                if let Some(c) = n.init { v.visit_node(c); }
                if let Some(c) = n.test { v.visit_node(c); }
                if let Some(c) = n.update { v.visit_node(c); }
                v.visit_node(n.body);
            }
            Node::JSXElement(n) => {
                v.visit_node(n.opening_element);
                for c in n.children.iter() { v.visit_node(c); }
                if let Some(c) = n.closing_element { v.visit_node(c); }
            }
            // ... every leaf ...
        }
    }

    pub fn mark_lists<F: FnMut(&NodeList<'gc>)>(&'gc self, cb: &mut F) {
        match self {
            Node::Program(n) => { cb(&n.body); cb(&n.decorations.get()); cb(&n.dummy_param_list.get()); }
            Node::JSXElement(n) => { cb(&n.children); }
            // ... only nodes that own ≥1 NodeList (child or decoration) get an arm; the rest fall to:
            _ => {}
        }
    }
}
```

> **`visit_children` walk order:** `.def` child fields in declared order, then decoration `NodeList`s (`decorations`, then `dummy_param_list`). For `mark_lists` the order is irrelevant (it only sets element mark bits). **Every `NodeList` — child OR decoration — must appear in both walks**, or its elements/nodes get swept (the GC bug the decoration-tracing test guards against).

    "as","break","const","continue","crate","dyn","else","enum","extern","false","fn","for","if",

def camel_to_snake(name):
    # CamelCase/lowerCamelCase -> snake_case, acronym-aware so JSX/TS/SH runs stay
    # together: JSXElement->jsx_element, TSTypeAliasDeclaration->ts_type_alias_declaration,
    # SHBuiltin->sh_builtin, typeAnnotation->type_annotation.

    return s.lower()

    s = camel_to_snake(json_name)

/// Counts children visited by the generated `visit_children`.
struct Counter(usize);
impl<'gc> ast::visitor::Visitor<'gc> for Counter {
    fn visit_node(&mut self, node: &'gc Node<'gc>) {
        self.0 += 1;
        node.visit_children(self);
    }
}

#[test]
fn range_predicates_match_kinds() {
    let mut ctx = Context::new();

    let prog = gc.alloc(Node::Program(Program::new(NodeMetadata::new(r()), NodeList::empty())));
    assert!(prog.is_function_like(), "Program is in the FunctionLike range");
    assert_eq!(prog.kind(), NodeKind::Program);

    assert!(fs.is_statement() && fs.is_loop_statement());
    if let Node::ForStatement(n) = fs { assert_eq!(n.label_index.get(), ast::node_child::INVALID_LABEL); }
