### D.1: WasmIRGen class skeleton
- **Files**: Created `include/hermes/WasmIRGen/WasmIRGen.h`, replaced `lib/WasmIRGen/WasmIRGen.cpp` (was placeholder). Modified `unittests/WasmIRGen/CMakeLists.txt` (added `hermesWasmFrontend` and `wabt` to link libraries). Replaced `unittests/WasmIRGen/WasmIRGenTest.cpp` (replaced placeholder with 10 real tests).
- **Decisions**: The `WasmIRGen` class stores `WasmModuleInfo &` and `IRBuilder` (no separate `Module &` — the builder holds the module). `createFunctions()` creates one IR Function per Wasm function (imported + defined), each with a "this" param (required by Hermes calling convention) plus one `JSDynamicParam` per Wasm parameter. Each function starts with a single basic block containing `ReturnInst(undefined)`. `beginFunction()` clears the placeholder return, creates `AllocStackInst` for params (initialized from `LoadParamInst`) and locals (initialized to zero). `endFunction()` emits `ReturnInst` with either the top of the value stack (if the function has results) or undefined. Instruction callbacks for constants, local.get/set/tee are implemented. The `irFunctions_` vector is indexed by Wasm function index. A `currentFuncIndex_` field tracks the current function being translated (avoids O(n) lookup in endFunction).
- **Issues**: Initial `TestModule` used `std::unique_ptr<Module>` which failed because `Value::operator delete` is private. Fixed by using stack-allocated `Module` (matches pattern in existing unit tests). Also, `M_` field initially caused an unused-private-field warning — removed it since the module is accessible via `builder_.getModule()`.
- **Notes for next step**: D.2 (Constants and locals) depends on D.1. `beginFunction` and the constant/local callbacks are already implemented in this step since the plan spec says D.2 is about making them work correctly end-to-end. The `WasmIRGen` is ready to be wired up to `BinaryReaderHermesIRGen` in D.13. The control flow stack (`ControlEntry`) is defined but not yet used — it will be populated by D.6-D.9.

### D.1.1: Wire wasm-to-IR pipeline and --dump-ir support
- **Files**: Modified `lib/WasmFrontend/WasmCompile.cpp` (replaced module info dump with WasmIRGen integration), `lib/WasmFrontend/BinaryReaderHermesIRGen.cpp` (added function body callbacks: `BeginCodeSection`, `BeginFunctionBody`, `OnLocalDecl`, `EndLocalDecls`, `EndFunctionBody`, `OnLocalGetExpr`, `OnLocalSetExpr`, `OnLocalTeeExpr`, plus `inFunctionBody_` dispatch in `OnI32ConstExpr`, `OnI64ConstExpr`, `OnF32ConstExpr`, `OnF64ConstExpr`), `include/hermes/WasmFrontend/BinaryReaderHermesIRGen.h` (added `setIRGen()`, `WasmIRGen*`, `inFunctionBody_`, `currentBodyFuncIndex_`, `currentLocalTypes_`, function body callback declarations), `include/hermes/WasmIRGen/WasmIRGen.h` (no new methods), `lib/CompilerDriver/CompilerDriver.cpp` (added `--dump-ir` support in `processWasmFile()`). Created 4 new D.1.1 lit tests: `irgen-return-param.wat`, `irgen-const.wat`, `irgen-local-tee.wat`, `irgen-locals.wat`.
- **Decisions**: Used single-pass architecture — `BinaryReaderHermesIRGen` populates `WasmModuleInfo` during module-level sections and dispatches function body callbacks to `WasmIRGen`. `BeginCodeSection` calls `WasmIRGen::createFunctions()` (all module-level sections are parsed by then). `EndLocalDecls` calls `WasmIRGen::beginFunction()` (after all local types are accumulated). Instruction callbacks check `inFunctionBody_` flag to distinguish function body context from init expression context. wabt's `BeginFunctionBody` `index` parameter is the full Wasm function index (not code-section-relative). Unimplemented function body instructions (e.g., `call`, `i32.add`, `global.get`) are silently no-ops — they produce incomplete IR but don't crash.
- **Issues**: (1) Initially computed `currentBodyFuncIndex_` as `importedFunctionCount() + index`, causing assertion failure. wabt already adds the import count to the index passed to `BeginFunctionBody`, so the correct value is just `index`. (2) The Wasm name section is parsed AFTER the code section, so function names from the name section aren't available when `createFunctions()` runs. Functions use `wasm_func_N` names for now. Name section support requires either a two-pass approach or post-creation renaming (Hermes `Function` has no name setter). This is deferred to a future improvement. (3) The old C.2.1 module-info-dump tests needed updating since the summary output was replaced by IR generation.
- **Notes for next step**: D.2 (Constants and locals) depends on D.1 and D.1.1, both now done. The constant and local callbacks are already wired end-to-end (verified by lit tests). D.2 may focus on correctness verification or adding i64 const support. All 12 wasm lit tests pass. The test pattern for future D.x steps is: `%wat2wasm %s -o %t.wasm && %hermesc --wasm --dump-ir %t.wasm | %FileCheck %s`.
