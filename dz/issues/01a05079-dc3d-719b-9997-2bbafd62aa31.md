All 8 `.run` tests under `test/napi/` carry their JavaScript as a
single-quoted string inside an `echo ... > %t.js` on the RUN line
rather than as the body of the file:

    test/napi/async-work-basic.run
    test/napi/async-work-many.run
    test/napi/compile-bytecode.run
    test/napi/load-native-module.run
    test/napi/run-bytecode.run
    test/napi/test_addon.run
    test/napi/tsfn-from-thread.run
    test/napi/typescript.run

The reason is mechanical: the tests need the built addon's path, which
is only available as the lit substitution `%napi_addon_dir`
(test/lit.cfg:184), and lit expands substitutions only in RUN lines,
never in the file body. Writing the JS as the file body would leave
`%napi_addon_dir` unexpanded.

The cost is that the test bodies are unreadable and unmaintainable -
no line breaks, no comments, no quotes of the outer kind, and a syntax
error in the JS surfaces as a lit failure rather than pointing at a
line. `test_addon.run` is seven `print()` calls on one line.

Two ways out, both already available on this branch:

1. `sed` the path into a real `.js` body, which is what
   `test/napi/text-encoder-napi.js:11` already does:

       // RUN: sed 's|ADDON_PATH|%napi_addon_dir/napi_text_encoder_addon.node|' %s > %t.js && %hermes ... %t.js

   This keeps the JS as the file body at the cost of one placeholder
   token.

2. Pass the addon path as a script argument and read it with
   `hermescli.getScriptArgs()` (lib/ConsoleHost/ConsoleHost.cpp:396),
   gated behind `-Xhermes-internal-test-methods`. This was the plan
   recorded when the tests were written, at a time when `hermescli`
   had not yet landed on this branch. It has since landed
   (ConsoleHost.cpp:674-721, with tests in test/hermes/hermescli*.js),
   so the approach is now viable.

Option 1 is the smaller change and needs no flag; option 2 removes the
placeholder entirely. Either is an improvement over the status quo.

Recorded here because the note lived only on the abandoned `old-n-api`
branch (history/n-api/TODO.md), whose code is otherwise fully
superseded by static_h.
