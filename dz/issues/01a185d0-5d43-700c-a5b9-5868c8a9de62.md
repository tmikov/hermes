Under HV32 (`HEAP_HV_PREFER32`, the Android default), the JIT gains far
less on numeric array code than under HV64. In the profiles, a third of
NavierStokes and a quarter of Crypto run in the generic PutByVal path,
which neither touches under HV64.

Octane, x86-64 Release, `HERMESVM_ALLOW_JIT=2`, built at 7357a443f,
from precompiled bytecode, `taskset -c 2`, median of 5:

| bench | interp HV64 | JIT HV64 | interp HV32 | JIT HV32 |
|---|---|---|---|---|
| NavierStokes | 5020 | 14500 (2.89x) | 4683 | 7109 (1.52x) |
| Crypto | 3051 | 7216 (2.37x) | 2922 | 5400 (1.85x) |
| Box2D | 12409 | 23857 (1.92x) | 11515 | 14409 (1.25x) |

The interpreter loses 4-7% to HV32 on these; the JIT loses 25-51%.

Profiles (`perf record -F 2000`, one run, `-Xjit`), share of samples:

| bench | mode | JIT code | top runtime symbols |
|---|---|---|---|
| NavierStokes | HV64 | 96.7% | none above 1.5% |
| NavierStokes | HV32 | 47.8% | putByValWithReceiver_RJS 16.9, ArrayImpl::_setOwnIndexedImpl 14.7, GC 6.8, _haveOwnIndexedImpl 2.0 |
| Crypto | HV64 | 95.8% | none above 1.5% |
| Crypto | HV32 | 69.7% | putByValWithReceiver_RJS 15.0, _setOwnIndexedImpl 8.9, _haveOwnIndexedImpl 1.6 |

`-Xjit-emit-counters`, NumByValDemotions: NavierStokes 34 under HV32,
0 under HV64; Crypto 36 against 25.

Likely cause, not verified: the inline PutByVal tier declines a number
that has to be stored as a boxed double, the site is demoted after
repeated declines, and every later store takes the generic helper. Box2D
shows the PutById side of the same problem (dz 01a04e00-0811).

First step: count declines per site, by reason, in NavierStokes'
`lin_solve`/`advect` loops and in Crypto's `am3`, to confirm the cause
before choosing a fix.

Reproduce: configure two Release trees, `HERMESVM_ALLOW_JIT=2`, one with
`HERMESVM_HEAP_HV_MODE=HEAP_HV_PREFER32`; compile each benchmark with its
tree's `hermesc -O -emit-binary`; run with `-Xjit` and `-Xjit=off`.
