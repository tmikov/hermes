Recorded as **§4.7** in the Wasm branch review (`wasm-old-rebased`). Residual
minors from the `.hbc` bytecode-gate work, triaged 2026-08-16 by the whole-branch
review of that pass. **All judged non-blocking — this issue exists so they are
not rediscovered from scratch, not because any of them blocks anything.**

## Diagnostics that exist but are not pinned

- The `fromHermesURL` error text now names the URL and distinguishes
  no-resolver / resolver-declined / registry-miss. No test asserts it;
  `e2e-from-hermes-url-noresolver.wat` checks only `e.name`.
- `e2e-from-hermes-bytecode.wat`'s gated-off arm asserts only `e.name`, so it
  cannot tell the gate's TypeError from a bad-argument TypeError. Mitigated: the
  two RUN lines share one driver and one `.hbc` and differ only in the flag, so
  the pair is still decisive.

## A test that could lose coverage silently

- Rows 1 and 2 of the sniff-gate matrix in `e2e-sniff-gate.wat` share an
  identical expected string, so silently dropping RUN line 2 would go unnoticed.
  Row 3 — the security-critical one — does have a unique string.

## Embedder-facing

- The APITest cases declare their resolver on the stack *after* the runtime, so
  it is destroyed first, violating the "must outlive the runtime" contract the
  header documents and that embedders will copy. No live UAF (nothing resolves
  during teardown). Fix: `setWasmModuleResolver(nullptr)` at test end, or relax
  the doc.
- `IWasmModuleProvider` is castable in `HERMES_ENABLE_WASM=OFF` builds, where
  registrations are silently inert. Probably the right ABI call, but undocumented.

## Cosmetic / known

- `getReplRuntimeConfig()` in `tools/hermes/hermes.cpp` does not wire the two new
  flags, so they cannot be enabled in the REPL. Fail-closed, and that builder is
  sparse by existing convention (it omits `EnableEval`, JIT and more).
- A non-ASCII URL renders as mojibake in the `fromHermesURL` TypeError
  (`TwineChar16` widens UTF-8 one byte per char); the URL is also unbounded.
- The `raise` / `clearThrownValue` / `callPromiseReject` block is duplicated
  between `wasmCompile` and `wasmInstantiate`. Pre-existing; they deliver errors
  differently, so folding them is not obviously right.
- `STR(fromHermesBytecode, ...)` sits in the CommonJS predefined-string cluster
  rather than the WebAssembly block. Moving it renumbers — do it with the
  `BYTECODE_VERSION` bump, not on its own.

## Process note attached to this pass

The branch is **not secure at every prefix**: the `.hbc` hole closes only at
`Stop WebAssembly entry points from content-sniffing .hbc by default`. The commit
order (gates -> `fromHermesBytecode` -> test migration -> the flip) was chosen so
every commit builds and passes the suite; it trades per-commit security for
per-commit greenness. **Land the set as a unit; do not cherry-pick a prefix.**
