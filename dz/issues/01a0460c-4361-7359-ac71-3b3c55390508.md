Recorded as **§4.1** in the Wasm branch review (`wasm-old-rebased`). This is the
one outstanding item where forgetting it silently miscompiles existing bytecode.

`BytecodeVersion.h` is still **99**. The branch carries an explicit
`Revert bytecode version to 99` commit, so the single bump is deliberately
deferred to the end — but it has since become load-bearing for three separate
pieces of work.

## Why it is now unavoidable

New `PRIVATE_BUILTIN`s are declared **above** `MARK_FIRST_JS_BUILTIN` in
`Builtins.def`, which shifts the `JS_BUILTIN` ids. Those ids are encoded as
`CallBuiltin` operands in compiled bytecode. The §4.4 internal-slots pass alone
added five (`wasmSetFuncInfo`, the two table funnel helpers, and the three link
builtins, minus those it removed); earlier work on this branch added others, and
§4.4 also *deleted* three predefined strings.

Failure mode if the bump is dropped: an `.hbc` compiled before the branch runs
against a VM built after it, the version check passes because both say 99, and
`spawnAsync` — or whatever now occupies that index — dispatches to a Wasm
builtin. Async functions are the first casualty.

## Also worth doing in the same change

`STR(fromHermesBytecode, ...)` currently sits in the CommonJS predefined-string
cluster rather than the WebAssembly block. Moving it renumbers the string table,
so the bump is the free moment to do it. (Recorded under §4.7.)

## Ordering

This stays **last** on the branch, after every other change that could add or
remove a builtin or a predefined string.
