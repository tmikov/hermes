Not a Wasm defect. Found 2026-09-14 while fixing 01a09e72-e936, whose
broken IR reached this path.

`verifyTryStructure` reports a block reachable from two different try
regions like this (`IRVerifier.cpp:415-421`):

    AssertWithMsg(
        enclosingInfo->second == succEnclosingTry,
        bbLabel(*succ)
            << " is reachable from multiple different TryStartInsts: "
            << iLabel(*succEnclosingTry) << " and "
            << iLabel(*enclosingInfo->second));

Either TryStartInst can legitimately be null -- "no enclosing try" is
exactly what `blockToEnclosingTry[&*F.begin()] = nullptr` records, and
it is one of the two values whenever a block is reachable both from
inside a region and from outside one. `iLabel` then dereferences it:

    #0 Instruction::getParent() IR.h:1233:12
    #1 Verifier::iLabel(Instruction const&) IRVerifier.cpp:160:43
    #2 Verifier::verifyTryStructure(Function const&) IRVerifier.cpp:416:9
    SUMMARY: AddressSanitizer: SEGV in Instruction::getParent()

So the verifier crashes instead of printing the error it had already
decided to print, and the shape it was about to name is precisely the
one a frontend is most likely to get wrong.

No longer reachable from the Wasm frontend now that branches close their
regions, which is why this is filed rather than fixed alongside: it
needs an IR-level test rather than a .wat one. The fix is to print
something for a null try ("the function body", say) rather than
formatting it as an instruction.
