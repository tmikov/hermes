`Object.freeze()` and `Object.seal()` on a function whose `length`, `name`
and `prototype` properties are still lazy mark the object as
frozen/sealed *before* those properties are materialized. The properties
are then created later with their default attributes, so a function that
reports `Object.isFrozen(f) === true` still has configurable — and
therefore deletable — own properties.

Repro: `test/hermes/lazy-function-freeze-seal.js`, currently committed
with `// XFAIL: *`. Remove the XFAIL when this is fixed.

Observed on `static_h` at db0c2ed9f, `hermes -O -target=HBC`. The print
format is `<prop> <value> <configurable> <writable>`:

```
freeze regular function
true                      <- isFrozen() claims frozen
length 3 true false       <- expected: length 3 false false
name foo true false       <- expected: name foo false false
prototype false true      <- expected: prototype false false
DID NOT THROW             <- delete f.length succeeded
DID NOT THROW             <- delete f.name succeeded
```

The same failure appears in all four freeze/seal sections of the test
(regular function, arrow function, sealed regular, sealed arrow).
`Object.preventExtensions()` is unaffected.

Two distinct defects are visible:

- freeze and seal both leave `length`/`name` configurable, which also
  makes them deletable and makes `isFrozen`/`isSealed` incorrect.
- freeze additionally leaves `prototype` writable. (Under seal,
  `prototype` staying writable is correct.)

The fix should force materialization of the lazy properties before the
object-integrity level is applied, so the attributes are computed
against real property slots.
