Found 2026-09-08 by external review while specifying reference-result
transport. **Identified by code inspection; a repro is the first thing this
issue needs.** Independent of reference types -- it is a defect in the
existing numeric multi-value path.

Numeric multi-value results travel in per-module buffers that are built from
**replaceable globals** and accessed with **ordinary property operations**:

- the buffers come from `globalThis.ArrayBuffer`, `globalThis.Uint32Array`
  and `globalThis.Float64Array` (`WasmIRGen.cpp:1458`)
- result stores and loads are ordinary indexed property accesses
  (`WasmIRGen.cpp:223`, `:313`)

So script can replace those constructors and supply storage whose indexed
getter or setter runs arbitrary JS. Two consequences:

**Substitution.** A replaced accessor can return a different number than the
one the callee stored, so a caller reads a value the callee never produced.

**Reentrancy against shared storage.** The buffers are per-module and reused
across calls. A setter that re-enters an export runs a second multi-value
call, which overwrites the buffer while the outer call's results are still
outstanding. The outer caller then reads a mixture of two activations. The
publication loops interleave stores and loads in signature order, so this
does not need an exotic signature -- `(result i32 i32)` suffices.

The import trampoline's two-pass scheme captures every result before writing
any buffer, which protects the conversion step, but the second pass is still
an ordinary write through replaceable storage (`WasmIRGen.cpp:2804`).

## Why this is filed separately

The reference-types work (`01a074ce-ac97`) gives reference results private,
per-activation storage, which protects **reference** identity. It does not
protect numeric results, and it would be dishonest for that spec to claim a
publication invariant covering "every result" while the numeric half remains
interceptable. So the reference work narrows its invariant to reference
results and points here.

## Fix direction

Allocate the return buffers intrinsically rather than through
`globalThis.*`, and access them through native builtins rather than ordinary
property operations -- the same treatment the reference container gets. That
closes substitution. Reentrancy additionally needs either per-activation
buffers or a guarantee that no script runs between the first committed result
and the caller capturing all of them.
