`loadNativeModule()` is defined as a bare global on every runtime the
`hermes` CLI creates (lib/ConsoleHost/ConsoleHost.cpp:604-613, inside
`#ifdef HERMES_ENABLE_NAPI`), alongside `print`, `loadSegment` and
`setTimeout`. It takes a filesystem path and dlopens it as a NAPI
addon (implementation at ConsoleHost.cpp:214).

Two problems:

1. It is not gated. Every other test-only utility is: `hermescli`
   (`loadFile`, `loadHBC`, `getScriptArgs`) is registered only when
   `-Xhermes-internal-test-methods` is set (ConsoleHost.cpp:674, guard
   `ctx.enableTestMethods_`), and `HermesInternal`'s test methods
   follow the same flag (lib/VM/JSLib/HermesInternal.cpp:899). A
   capability that loads and executes arbitrary native code from a
   path should not be the one exception that is always on.

2. It is in the wrong place. `hermescli` is where CLI-only host
   utilities now live; a bare global is both inconsistent and a
   namespace collision hazard for scripts run under the CLI.

The fix is to move it to `hermescli.loadNativeModule` and register it
inside the existing `ctx.enableTestMethods_` block using the same
`defineMethod` lambda as the other three.

Note this is deliberately scoped as hygiene, not as a sandbox escape:
a script that reaches `loadNativeModule` is already running under the
`hermes` CLI, which executes whatever JS it is given. The argument is
consistency with how every neighbouring test hook is gated, and
keeping the default global namespace clean.

Callers to update: the `.run` tests under test/napi/ that invoke
`loadNativeModule` (async-work-basic, async-work-many,
load-native-module, test_addon, tsfn-from-thread) would need
`-Xhermes-internal-test-methods` added to their `%hermes` invocation,
which `test/napi/text-encoder-napi.js:11` already passes.
`load-native-module.run` also asserts `typeof loadNativeModule` from
JS and would need updating to the new name. This overlaps with the
sibling issue on those tests' RUN lines, so the two are worth doing
together.

When the note was written, `hermescli` had not yet landed on this
branch and this was blocked on it. It has since landed, so the work is
now unblocked.

Recorded here because the note lived only on the abandoned `old-n-api`
branch (history/n-api/TODO.md), whose code is otherwise fully
superseded by static_h.
