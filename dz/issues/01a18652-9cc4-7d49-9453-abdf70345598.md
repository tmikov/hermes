The plugin's locale data is ICU4X 2.3's compiled data, which is CLDR
48.2, and the CLDR-derived files under intl/core/data/ that
update-cldr-lists.py generates are also from CLDR 48.2. A locale, time
zone or formatting change in a newer CLDR does not reach users until the
plugin moves.

The ICU4X crates are held on 2.3.x on purpose: intl/core/Cargo.toml uses
`~` requirements for them, and the lock file must not mix ICU4X minor
versions (Cargo unifies 2.x, so a single crate moving to 2.4 drags the
others). The upgrade is therefore all of them together, including
icu_experimental, which must move to its release that matches ICU4X 2.4.

The upgrade also fixes 01a17bdc (quadratic word segmentation of long
unbroken CJK or Thai runs), which ICU4X 2.4 resolved.

What it involves:
- Move every ICU4X crate (and icu_experimental) to the 2.4 line and
  update Cargo.lock; fix any API changes in intl/core.
- Regenerate intl/core/data/*.txt with update-cldr-lists.py against
  CLDR 49, so the generated files and ICU4X's compiled data agree.
- Rerun check-intl, including plugin-mode test262, and update
  intl/test/test262-expectations.txt for tests that change outcome.
- Update the spec (doc/superpowers/specs/2026-10-22-intl-plugin-design.md:
  Build's version pin, the Data section's CLDR references, the
  Segmenter risk) and the sizes.
