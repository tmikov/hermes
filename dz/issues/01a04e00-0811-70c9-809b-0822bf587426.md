Under HV32, Octane Box2D declines 63.6% of inline-tier entries (its
stores are mostly non-compressible doubles that must be boxed). Hoisting
the encode ahead of the guards (faa6c94b3) halved the regression
(-2.5% -> about -1.1%; a later controller A/B read +1.8%, so the residual
is inside noise). If it is real, the named fix is a per-site record
(e.g. a bit in the write cache entry or a per-site counter) so a site
that always declines stops entering the tier and takes the helper
directly. Measure first with a scratch decline counter (the one used in
the Stage 4 report) before building anything.
