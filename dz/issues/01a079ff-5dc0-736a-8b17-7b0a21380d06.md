Found 2026-09-07 by external review of `01a079c6-fdd6`, then measured.

Exporting one global under two names produces two distinct
`WebAssembly.Global` objects. The JS API requires one.

Recorded for completeness rather than urgency: **Node has the same bug**, and
both engines get the memory case right, so nothing in the wild is likely to
depend on it. Filed so it is not rediscovered.

## Measured

```wat
(module (memory (export "m1") 1) (export "m2" (memory 0))
        (global (export "a") i32 (i32.const 7)) (export "b" (global 0)))
```

```
                                              Hermes    Node v24.13.1
one global, two export names -> same object:   false      false
one memory, two export names -> same object:   true       true
```

## Why one object is required

"Create a global object" begins: "Let map be the surrounding agent's
associated Global object cache. If map[globaladdr] exists, return
map[globaladdr]." "Initialize a global object" ends: "Set map[globaladdr] to
global." "Create an exports object" reaches a global export through that same
algorithm, so the second export of one global address must return the first
object. The cache is per-AGENT. There is no exception for defined globals or
for immutable ones.

## Mechanism

`finalizeModule()`'s global export loop constructs one Global per export
ENTRY (`WasmIRGen.cpp:2154`), with no cache keyed on the global index.

## Fix

Construct and memoize one Global per GLOBAL INDEX and publish that object
under every export name that references it. That also subsumes the imported
re-export case if the imported object seeds the cache.

## Related

- `01a079c6-fdd6` -- exported mutable global is a snapshot. Its fix requires
  only STORAGE coherence across export names (a write through either name is
  visible through both), which holds without this because both objects would
  be closure-backed to the same frame slot. This issue is the `===` half.
- Re-exporting an imported immutable global -- the same cache rule, and there
  Hermes is wrong while Node is right.
