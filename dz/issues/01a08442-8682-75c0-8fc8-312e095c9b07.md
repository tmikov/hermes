include/hermes/VM/NativeFunctions.def has a HERMES_ENABLE_WASM block listing wasm builtins. That
list generates the pointer-to-name table in lib/VM/JSNativeFunctions.cpp:52; a missing entry
makes the lookup return "" at line 83, and lib/VM/Callable.cpp:1148 uses that lookup to name
native functions in heap snapshots.

Eight wasm builtins are missing from the list:

  wasmGlobalGet   wasmGlobalSet   wasmLinkError   wasmLinkGlobal
  wasmLinkMemory  wasmLinkTable   wasmMakeGlobal  wasmNearest

(A ninth, wasmIsExportedFunction, was found at the same time and is registered by the commit
that files this issue, since it was added by that same work.)

Effect: these eight native functions appear unnamed in heap snapshots. Dispatch, startup
registration and the Wasm-disabled id range are all unaffected -- this is diagnostic metadata
only, which is why it has gone unnoticed.

Why it is worth recording rather than just fixing: NativeFunctions.def is a FOURTH registration
point for a new Wasm builtin, and it was missing from the recipe. The known recipe was three
edits -- the Builtins.def declaration, the PredefinedStrings.def string, and moving the
hardcoded endpoint of the Wasm-disabled registration id range. Two independent reviewers
checked a new builtin against that three-edit recipe and both concluded it was exhaustive; a
third found this list. Anyone adding a Wasm builtin should be told there are four.

Note the cluster: wasmMakeGlobal, wasmGlobalGet, wasmGlobalSet and wasmLinkGlobal are the
globals builtins added by recent work, which suggests the omission propagates by copying the
most recent neighbour's registration rather than by consulting a checklist.

    THE REGISTRATION RECIPE, CORRECTED AND IN CHECKABLE FORM.

    Context for why this belongs here: two independent reviewers checked a newly added Wasm builtin
    against a THREE-edit recipe and both concluded it was exhaustive. A third reviewer found the
    fourth. The recipe itself was wrong, in the document both reviewers were handed as authority,
    so "have a reviewer check it" is demonstrably not a control for this.

    State it as: DECLARE the builtin, then satisfy FOUR registration obligations. That is five edit
    sites in total -- the declaration must not displace the enabled registration in the checklist,
    which is how the miscount arose.

      Declaration          WASM_BUILTIN(<name>) in include/hermes/FrontEndDefs/Builtins.def
      Obligation 1         defineInternMethod in the enabled block of lib/VM/JSLib/HermesBuiltin.cpp
      Obligation 2         STR(<name>, "<name>") in the WASM block of include/hermes/VM/PredefinedStrings.def
      Obligation 3         the hardcoded endpoint of the Wasm-DISABLED registration id range
      Obligation 4         NATIVE_FUNCTION(<name>) in the HERMES_ENABLE_WASM block of
                           include/hermes/VM/NativeFunctions.def   <-- the one that was missing

    The checks that would make each obligation self-enforcing rather than review-dependent:

      Obligation 1   Resolve the declared id; assert the intended implementation pointer and arity;
                     invoke it on meaningful inputs.
      Obligation 2   Require exactly STR(N, "N") inside the enabled block; assert the callable's
                     `name` equals N.
      Obligation 3   Derive the expected ids from the WASM_BUILTIN declarations; assert every id
                     resolves to the shared disabled implementation. This must RUN a Debug runtime
                     initialization -- compiling and linking the Wasm-off binary does not detect an
                     omission, because the completeness assertion fires at runtime init.
      Obligation 4   Assert getFunctionName(registeredPointer) equals the implementation name.

    Generate the audited builtin set from Builtins.def rather than maintaining a second handwritten
    list -- a handwritten list is how obligation 4 drifted in the first place. Also check
    declaration uniqueness, contiguous Wasm placement before _firstJS, identical ids across the
    enabled and disabled configurations, and endpoint equality with the final Wasm declaration.
    Allow exactly the eight legacy metadata omissions tracked by this issue and reject new ones.
    Demonstrate the checks bite by removing each obligation in turn and watching its own check fail.

    NO FIFTH OBLIGATION EXISTS, checked deliberately. Counts and enum boundaries derive from
    Builtins.h:24; builtin storage derives from _count at Runtime.cpp:328; printable builtin names
    and JS registration derive from Builtins.def at Builtins.cpp:28 and Runtime.cpp:1908. All of
    those track the declaration automatically. That consumer audit is worth preserving next to
    whatever tests get written, because it is the evidence that four is the whole list.
