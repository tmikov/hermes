Found 2026-09-14 by an external review of the `try`-with-result fix, and
verified against the compiler.

`onDelegate` (`WasmIRGen.cpp:6195`) never reads its `depth` argument. It
emits a synthetic catch block that simply throws again (`:6219-6221`),
and `Analysis.cpp:380` assigns that throw to the NEAREST enclosing try.
So every `delegate` behaves as `delegate 0` regardless of what the module
wrote, and a delegation meant to skip a handler lands in it instead.

The spec suite's own `delegate-skip`
(`external/wasm-testsuite/tests/legacy/try_delegate.wast:31`, asserted at
`:203`) is exactly this case:

    (func (export "delegate-skip") (result i32)
      (try $t (result i32)
        (do (try (result i32)
              (do (try (result i32) (do (throw $e0) (i32.const 1))
                    (delegate $t)))
              (catch $e0 (i32.const 2))))
        (catch $e0 (i32.const 3))))

    spec says 3; Hermes returns 2

`try_delegate.wast` is not among the `.wast` files wired into
`test/wasm/spec/`, which is why nothing caught this. Wiring it in is
probably how the fix should be checked.

    Fixed. onDelegate's synthetic handler now leaves every protected region
    the delegation skips before it rethrows, using the same TryEndInst chain
    a branch uses. The exception then arrives as though thrown at the target
    label's position, which is what delegate means.

    The entry has already been popped when onDelegate runs, so depth counts
    from the enclosing scope -- the way `delegate l` numbers its label -- and
    the regions to leave are those at indices 0 through depth-1. The
    target's own region is deliberately not left: if the target is a try,
    that is the one being handed the exception; if it is a block or a loop
    there is nothing of its own to leave and the throw lands in whatever
    encloses it, which is what delegate-to-block requires.

    test/wasm/e2e-try-delegate.wat is the spec suite's own module and its
    own expected answers. It could not be wired into test/wasm/spec/: the
    file also contains return-call-in-try-delegate and
    return-call-indirect-in-try-delegate, and `return_call` is the tail-call
    proposal, which this frontend does not support, so the module fails to
    load on that opcode and takes every delegate assertion with it. Those
    two functions are the only ones dropped.

    All 18 rows match the spec. Three of them change with the fix:

      delegate-skip:             2 -> 3
      delegate-to-caller-skipping: silently swallowed -> escapes
      delegate-targets-obs:      90 -> 1

    The rest are delegate-0 shapes, which the old code already got right by
    accident.

    Found on the way and filed: catch_all catches traps (01a09ecf-3a80).
    That is why the spec's own delegate-correct-targets cannot discriminate
    here -- a wrong landing traps and the trap is caught by the outermost
    handler, giving the same answer -- and why delegate-targets-obs exists
    beside it.

    Corrections from the review of the fix.

    "All 18 rows match the spec" undercounted and overclaimed at once: 18 of
    the rows are the spec's, delegate-targets-obs is this file's own, and
    four more have been added since (delegate-skip-two, delegate-past-block,
    delegate-to-loop). The spec file has 20 invocation assertions; the two
    omitted are the tail-call ones.

    "The rest are delegate-0 shapes" was wrong. delegate-correct-targets has
    two positive-depth hops, and both break-and-* functions contain depth-2
    delegations -- their synthetic handlers simply never run, because those
    bodies branch rather than throw.

    What the review found that mattered more: everything the spec module
    EXECUTES skips exactly one region, so closing entry 0 and stopping would
    have satisfied all of it. Three cases were added for that, and each
    separates a different mistake:

      delegate-skip-two    6 correct / 5 if the chain stops after one region
                           / 4 if the depth is ignored
      delegate-past-block  a block between the try and its target, which the
                           label count includes but which is not a region --
                           closing `depth` REGIONS rather than walking
                           `depth` labels closes the target and lets the
                           exception escape
      delegate-to-loop     a loop as the target

    Mutations run: emitBranchTryEnds(0) gives delegate-skip-two 5;
    emitBranchTryEnds(depth), closing the target too, makes
    delegate-throw(1), delegate-merge(0,1) and delegate-skip escape and
    delegate-targets-obs return 92; no chain at all gives 2 / undefined / 90
    / 4.

    The driver also accepted any JS throw where the spec's assert_exception
    wants an uncaught Wasm exception. It now checks the carrier -- the tags
    are exported for it -- and a trap reads as "NOT A WASM EXCEPTION: Error:
    unreachable executed" rather than passing.
