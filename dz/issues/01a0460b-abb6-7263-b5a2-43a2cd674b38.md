Recorded as **H21** in the Wasm branch review (`wasm-old-rebased`). Pre-existing;
found 2026-08-26 by the §4.4 final review.

`onCatch` (`WasmIRGen.cpp:5386-5400`) loads exception payload elements with
`LoadPropertyInst` and pushes them onto the Wasm value stack with **no
coercion**. With an exported tag and an imported JS function that throws
`[tag, ...poison]`, arbitrary JS values reach a module's typed globals:

```
obj getg    = [object Object]      // an exported (result i32) function
obj getgf   = [object Object]      // an f64 global
strings getgf = abc
```

## Why this is not urgent

Not memory-unsafe, and it fails closed in the worst cases. Globals are `:any`
Variables, so an `AsNumberInst`/`BinaryUnsignedRightShift` is inserted at every
typed use. Any payload that crosses the catch->continuation edge fails to compile
outright (`Operand %8 must dominate the Instruction %2` -> `Lowered IR
verification failed`, exit 8) — that is a *separate* pre-existing IRGen bug, and
it is why no existing test uses a payload at all: `e2e-cross-module-tag.wat` only
`drop`s them.

## Why it is worth recording

The §4.4 design enumerated the inbound JS->Wasm routes as `Table.prototype.set`
and funcref parameters. This is a third that neither the design nor its proof
obligation named. Task 6's "twenty routes" enumeration test is complete for the
**outbound** direction only — worth stating plainly, because the name suggests
otherwise, and a future reader may take it as covering both.
