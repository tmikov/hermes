`Test262Suite.run_test` writes two variants of every test that has neither
`onlyStrict` nor `noStrict` (or `raw`): one with a `'use strict';` prologue
and one without. Both variants are then compiled with the same
`CompileRunArgs`, whose `strict_mode` is the test's own: `StrictMode.ALL`
(`utils/testsuite/preprocess.py:66`, in `generate_test262_source`).

`compile_and_run_single` adds `-strict` whenever
`StrictMode.STRICT in compile_run_args.strict_mode`
(`utils/testsuite/hermes.py`, `compile_and_run_single`; the same test
appears in `run()` for `--lazy`). `StrictMode.ALL` contains `STRICT`, so the
"non-strict" variant is compiled with `-strict` too. In normal mode, test262
tests that may run in either mode never run sloppy.

Shown with a synthetic test that throws only when `this` is undefined in a
plain function call: with the plugin mode's per-variant strictness removed,
the non-strict variant fails too.

Fix: compile each variant with its own strictness, `StrictMode.STRICT` for
the `.strict` file and `StrictMode.NO_STRICT` for the other. Expect new
failures once sloppy mode actually runs.

The Intl plugin mode (`--intl-plugin`) is not affected: it runs each variant
with `dataclasses.replace(compile_run_args, strict_mode=...)`.
