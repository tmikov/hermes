Only the Linux test262 job (`.github/workflows/build.yml`,
`test-linux-test262`) builds the Intl plugin and runs `check-intl`. Every
macOS job configures with `HERMES_BUILD_INTL=OFF`: `test-macos-test262` and
CircleCI's `test-macos` test the old, built-in Intl, and `macos` builds a
universal binary, for which the plugin defaults to OFF.

So the macOS-only paths are checked only by hand on a Mac (Phase 0,
Task 13):
- the `.dylib` build with `-undefined dynamic_lookup` and
  `-Wl,-exported_symbol,_hermes_intl_get_entry` (`intl/CMakeLists.txt`);
- the loader's macOS default resolution: `proc_pidpath` for the main
  executable and `_dyld_get_image_header(0)` in `isMainExecutable`
  (`API/hermes/IntlPluginLoader.cpp`);
- CoreFoundation detection in `intl/jsi/Defaults.cpp`.

Fix: add a single-architecture macOS job (or matrix row) that installs
Rust, configures with `HERMES_BUILD_INTL=ON` and
`HERMES_INTL_TEST262_DIR`, and runs `check-hermes` and `check-intl`.
