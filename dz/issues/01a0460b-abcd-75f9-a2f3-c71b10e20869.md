Recorded as **H22** in the Wasm branch review (`wasm-old-rebased`). Two low-impact
carries from the §4.4 internal-slots pass, filed together so neither is
rediscovered from scratch.

## 1. A defined table's limits are checked; its freshness is not

The defined-table limits check added at the end of §4.4 verifies the *shape* of
whatever `globalThis.WebAssembly.Table` returned — entry count and maximum, exact
equality, one LinkError. It does not verify that the object is fresh, so a
substituted genuine, correctly-shaped Table still links.

This is identical to the memory case §4.4 accepted deliberately, and writes
through such a table still go through the funnel, so it grants nothing that a
table *import* would not already grant. Recorded as a known limit, not a defect
to fix blindly.

## 2. Cross-role table array aliasing has no test

`wasmTableCopySlots` picks its copy direction by comparing **all six** arrays —
every destination against every source — so that a shared array is copied in an
overlap-safe direction whatever role it plays. Same-role aliasing (two tables
sharing an `exported` array) is covered by `e2e-table-copy-alias`. **Cross-role**
aliasing — one table's `funcs` array being another's `types` — is handled
correctly by the predicate but is exercised by nothing.

Reachable the same way the tested case is: an externref table's three arrays are
three independent `new Array(n)` calls off a replaceable `globalThis.Array`, so a
driver can arrange any pairing by call order.

Note the ledger previously implied Task 4's externref test had overtaken this. It
had not — that test shares the *exported* array, which is same-role.
