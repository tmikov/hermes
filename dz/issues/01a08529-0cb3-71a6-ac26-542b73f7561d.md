JSWebAssemblyGlobal::setValue and setNumberValue are private, with the storage funnel
setWasmGlobalValue as their only friend. That is deliberate: it keeps the set of writers to
value_ small enough to read.

JSWebAssemblyGlobal::setI64Value is PUBLIC and also writes value_, so it is a second route to the
slot that does not go through the funnel. It has four callers, all in lib/VM/JSLib/:

  lib/VM/JSLib/HermesBuiltin.cpp:2662, :2865
  lib/VM/JSLib/WebAssembly/WebAssembly.cpp:2410, :2586

Making it private with the same friendship would close that route rather than document it. Nothing
outside lib/VM/JSLib/ calls it, so the change looks small.

Why it was not done when it was found: it surfaced in a fix round scoped to correcting a comment
about exactly this encapsulation, and that one sentence had already been wrong three times.
Reshaping the encapsulation in the same round would have staled the corrected comment a fourth
time. The comment now describes the public route accurately, so nothing is misleading in the
meantime -- this is a tidy-up, not a defect.

Worth doing together with the comment update, so the two do not drift apart again.
