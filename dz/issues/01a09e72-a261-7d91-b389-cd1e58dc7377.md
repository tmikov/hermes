Found 2026-09-14 by an external review of the `try`-with-result fix, and
verified against the compiler.

`addBranchPhiOperands` and `peekBranchPhiOperands` both admit
`ControlEntry::Try` now, but `onBrTable`'s own inline operand loop
(`WasmIRGen.cpp:4531`) still tests only `Block` and `If`. Its branch at
`:4561` targets `entry.contBlock` regardless, so a `br_table` whose
target is a `try` reaches the continuation contributing nothing to its
result phis.

The phi then carries only the operands the other edges supplied, and the
value that edge meant to deliver is silently replaced by whichever one
did arrive:

    (module
      (import "e" "boom" (func $boom))
      (func (export "p") (result i32)
        (try (result i32)
          (do (call $boom) (i32.const 9))
          (catch_all (i32.const 7) (br_table 0 (i32.const 0))))))

    no throw: 9    (correct)
    caught:   9    (should be 7)

It compiles and runs; only the answer is wrong. The fix is the same
three-kind test the two helpers now use.
