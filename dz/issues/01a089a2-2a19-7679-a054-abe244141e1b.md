The vendored wabt 1.0.39 (`external/wabt`) cannot parse a `$name` reference to
a global inside an element expression. It aborts:

    wat2wasm: external/wabt/wabt/include/wabt/ir.h:59:
      Index wabt::Var::index() const: Assertion `is_index()' failed.

Reproducer:

    (module
      (import "e" "g" (global $g funcref))
      (table 2 funcref)
      (elem (i32.const 0) funcref (item (global.get $g))))

Replacing `$g` with `0` parses. A named `ref.func $f` in the same position is
fine, so it is specific to `global.get`: the name is never resolved to an
index before the elem-expr writer reads it.

Affects test authoring only -- Hermes reads the binary, and the binary wabt
produces from the numeric form is correct.
`test/wasm/e2e-elem-mixed-items.wat` and
`test/wasm/e2e-elem-passive-items.wat` use numeric global indices and say why.

Fix upstream, or carry a patch in `external/wabt`.
