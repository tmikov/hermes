Found 2026-09-14 by an external review of the `try`-with-result fix, and
verified against the compiler.

`onBr` (`WasmIRGen.cpp:4438`), `onBrIf` (`:4466`) and `onBrTable`
(`:4561`) emit a plain `BranchInst` when the branch leaves a `try` body.
Nothing emits the `TryEndInst` that closes the protected region, which
only `onCatch`, `onCatchAll`, `onDelegate` and `onEnd` do.

`Exceptions.cpp:61` walks forward from the `TryStartInst` adding every
block it reaches to the enclosing exception region, and stops that walk
only at a `TryEndInst` or a throw (`:68-81`). A branch out of the body
therefore carries the region with it, and the region never closes.

The simplest shape does not even compile:

    (module
      (import "e" "boom" (func $boom))
      (tag $t)
      (func (export "p") (result i32)
        (block $out
          (try (do (br $out)) (catch_all (i32.const 0) (drop))))
        (call $boom)
        (i32.const 3)))

    ReturnInst %8 but Try %0 has not been closed. in function "wasm_func_1"
    error: Lowered IR verification failed

and the emitted `wasm_func_1` has a `TryStartInst` with no `TryEndInst`
anywhere. Where the verifier does not catch it -- a shape whose region
happens to be closed by some other path -- the consequence is worse than
a compile failure: code after the `br` stays covered by a handler it has
already left, so an exception raised there is swallowed by it.

Both halves of the fix are needed: emit `TryEndInst` for each `try` the
branch crosses, innermost outwards, and do it on all three branch
instructions.
