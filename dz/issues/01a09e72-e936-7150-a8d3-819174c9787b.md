Found 2026-09-14 by an external review of the `try`-with-result fix, and
verified against the compiler.

`onBr` (`WasmIRGen.cpp:4438`), `onBrIf` (`:4466`) and `onBrTable`
(`:4561`) emit a plain `BranchInst` when the branch leaves a `try` body.
Nothing emits the `TryEndInst` that closes the protected region, which
only `onCatch`, `onCatchAll`, `onDelegate` and `onEnd` do.

`Exceptions.cpp:61` walks forward from the `TryStartInst` adding every
block it reaches to the enclosing exception region, and stops that walk
only at a `TryEndInst` or a throw (`:68-81`). A branch out of the body
therefore carries the region with it, and the region never closes.

The simplest shape does not even compile:

    (module
      (import "e" "boom" (func $boom))
      (tag $t)
      (func (export "p") (result i32)
        (block $out
          (try (do (br $out)) (catch_all (i32.const 0) (drop))))
        (call $boom)
        (i32.const 3)))

    ReturnInst %8 but Try %0 has not been closed. in function "wasm_func_1"
    error: Lowered IR verification failed

and the emitted `wasm_func_1` has a `TryStartInst` with no `TryEndInst`
anywhere. Where the verifier does not catch it -- a shape whose region
happens to be closed by some other path -- the consequence is worse than
a compile failure: code after the `br` stays covered by a handler it has
already left, so an exception raised there is swallowed by it.

Both halves of the fix are needed: emit `TryEndInst` for each `try` the
branch crosses, innermost outwards, and do it on all three branch
instructions.

    The compile failure is not the whole of it, and not the worst of it.

    `IRVerifier.cpp:365` rejects a RETURN under an open try, which is why
    the `br $out` shape in the report is caught. It checks only returns, so
    a shape that leaves the region open without returning through it
    compiles -- and then `fixupCatchTargets` (`Analysis.cpp:380`) assigns
    later throws to the handler the code has already left.

    Executed, not deduced:

        (module
          (tag $t)
          (func (export "p") (result i32)
            (try
              (do (br_table 0 (i32.const 0)))
              (catch_all (return (i32.const 1))))
            (throw $t)))

        p() returned 1

    The `throw $t` is AFTER the try. It should escape the function; instead
    the try's catch_all caught it and returned 1. Nothing in the compiler
    complained.

    So the defect has two faces: valid modules that will not compile, and
    valid modules that compile into something that silently routes an
    exception to the wrong handler. The second is the reason to fix it.
- 2026-09-14T07:05:57.904Z  Tzvetan Mikov <tmikov@gmail.com>  status: open -> closed (fixed)
    Fixed. A branch now emits one TryEndInst per region it leaves, innermost
    first, each in its own block -- and `return` does the same for every
    region it is inside, which was the same defect: a ReturnInst under an
    open try is what the verifier refuses, and nothing had closed the region
    for it either.

    The order matters to both consumers. The verifier tracks the innermost
    enclosing try per block and requires each TryEndInst's catch target to
    match it; Exceptions.cpp hands the block after a TryEndInst back to the
    enclosing level, which then meets the next one.

    A try whose HANDLER is running is skipped: onCatch/onCatchAll closed
    that region already, and closing it twice is rejected as "TryEnd without
    an enclosing TryStart".

    The chain moves where the branch is emitted from, so a branch carrying a
    result records its phi operands at the END of the chain. One crossed
    region does not show this -- the chain is then a single empty block that
    a later pass merges into the block the branch was written in, so either
    choice produces identical IR. Two do, and the test has value-carrying
    br, br_if and br_table across two tries for that.

    Every part of the fix was mutation-checked; each of these makes a named
    check fail:

      onBr / onBrIf / onBrTable / onReturn without the chain
      the chain closing only the innermost region
      the chain without the inCatch guard
      the phi operands recorded before the chain instead of after (all three
        branch instructions)

    unsupported, 0 unexpected.
