Recorded as **§5.1a** in the Wasm branch review (`wasm-old-rebased`).
**Blocked** until the branch rebases onto `origin/static_h`.

The `.hbc` bytecode-gate work added `EnableUntrustedBytecodeFromJS` and
`EnableWasmBytecodeContentSniffing` to `RuntimeConfig`, gating every JS route by
which bytecode can be handed to the engine.

`origin/static_h`'s Worker implementation accepts an ArrayBuffer / TypedArray /
DataView via `copyBufferBytes`, which is another such route. **This branch cannot
see that yet** — its own Worker is string-only, so the gate has nothing to attach
to here, and the branch cannot rebase while the merge with the divergent `wasm`
line is in flight.

## What to do, after the rebase

Apply the same `EnableUntrustedBytecodeFromJS` gate to the Worker's buffer-taking
entry point, so the bytecode trust boundary is uniform across every JS route
rather than closed on the WebAssembly ones and open on the Worker one.

Do not attempt before the rebase: the code to gate is not present.
